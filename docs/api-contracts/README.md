# API 계약 우선 작업 방식

백엔드 전담 범위는 API·인증/인가·PostgreSQL·JPA·비즈니스 규칙·Validation·예외처리·테스트·API 명세다. 프론트 구현은 담당하지 않는다.

1. developer를 기준으로 기능 브랜치를 만든다. PM 공통 기준에 따라 새 작업은 codex/<기능>-<작업>으로 분리하고 기존 진행 feature/*는 보존한다. 미병합 기능에 의존하면 선행 PR과 누적 범위를 명시한다.
2. 구현 전에 이 폴더에 HTTP 경로/메서드, 인증/소유권, 요청·응답 예시, 필수/nullable/범위, 오류코드, 동시수정·재시도 계약을 먼저 커밋한다.
3. 프론트는 이 계약으로 연결을 준비할 수 있다. 완료된 것으로 오인하지 않도록 상태를 ‘계약 확정/구현 중/검증 완료’로 표기한다.
4. 서비스와 DB 변경, 테스트를 구현하고 생성 OpenAPI와 문서를 대조한다.
5. developer 대상 PR에 구현 API·마이그레이션·검증·다음 작업을 짧게 기록한다. main/developer를 직접 수정·병합하지 않는다.

기능마다 쉬운 한국어 주석으로 역할과 중요한 변경 주의점을 설명한다. 계약을 바꿀 때는 호환 여부와 변경점을 문서에 먼저 남긴다.
