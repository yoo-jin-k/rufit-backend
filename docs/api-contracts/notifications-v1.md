# 서버 알림 v1 — 친구 신청과 수락

로그인 Bearer 인증을 사용합니다. recipient/owner는 요청에서 받지 않고 인증 계정으로 결정합니다.

## 조회
`GET /api/v1/social/notifications?before=123`
- before: 선택 양의 정수 커서. 기본 최신부터 30개, 추가 1개로 hasNext 판단.
- 응답 200: `{items:[{id:"123",type:"FRIEND_REQUEST",actorId:"UUID",actorNickname:"닉네임",requestId:"UUID",createdAt:"ISO-8601",read:false}],unreadCount:1,hasNext:false}`
- type: FRIEND_REQUEST / FRIEND_ACCEPTED. bigint id는 JSON 문자열입니다.
- 검색용 프로필 미등록 계정은 빈 목록/0을 반환합니다. 조회만으로 읽음 처리하지 않습니다.
- 취소/거절/처리 완료된 신청 알림은 제외합니다. 수락 알림은 친구 관계가 남아 있을 때만 표시합니다. 양방향 차단된 상대는 제외합니다.
- 현재 닉네임만 표시하며 사진/비공개 계정 식별자를 노출하지 않습니다.

## 읽음
`POST /api/v1/social/notifications/{id}/read`, body 없음 → 204.
본인에게 현재 보이는 알림만 처리합니다. 반복 요청은 204, 다른 사람/사라진 알림은 404.
알림 클릭 또는 해당 친구 신청 처리 시 읽음 상태를 반영합니다.

## 이벤트와 재시도
- 친구 신청과 알림 생성을 동일 DB 트랜잭션으로 처리합니다.
- 친구 수락 시 신청자에게 수락 알림을 생성합니다. 동일 신청 재시도로 중복 생성하지 않습니다.
- 기존 대기 신청은 마이그레이션으로 알림을 보충합니다. 과거 수락 이력은 소급 생성하지 않습니다.
- 클라이언트는 활성 화면에서 30초마다/앱 복귀/알림 열기/처리 후 갱신합니다. OS 푸시 알림이 아닙니다.
- 오류는 기존 ProblemDetail: 400 형식, 401 미인증, 404 소유권/대상 없음.

## 후속 의존 작업
좋아요·응원은 서버 게시물 공개/좋아요 및 운동 중 상태·응원 이벤트 저장이 아직 없어 이번 계약에 포함하지 않습니다. 로그인 계정에 로컬 가상 알림을 섞지 않습니다.
