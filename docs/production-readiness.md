# 운영 DB와 보안 준비 메모

2026-09-13 사용자 요청을 반영한다. 개발 중 기능 검증과 실제 서비스 운영 준비를 구분한다.

## DB를 사용자가 지금 만들어야 하나

지금 개발을 이어가기 위해 별도 DB를 직접 만들 필요는 없다. 개발 구성(compose.yaml)과 전용 테스트 PostgreSQL은 준비돼 있으며 실제 검증은 localhost:5435의 rufit_test에서 한다. 테스트 자료는 검증 중 초기화될 수 있으므로 실제 사용자 데이터를 넣지 않는다.

개발용 rufit DB 구성은 localhost:5433에만 열고 이름 있는 볼륨에 저장한다. 애플리케이션 실행 시 Flyway 마이그레이션으로 테이블을 관리하므로 ERD대로 수동 생성할 필요는 없다. 운영 DB는 아직 생성·연결·배포하지 않았다. 서비스 출시 전 운영용 PostgreSQL과 접속 정보를 준비해야 하며, 호스팅 계정·비용·지역·용량을 정한 뒤 기존 마이그레이션으로 구조를 만든다. 운영 DB를 테스트용 DB로 대체하지 않는다.

## 현재 검증된 범위와 출시 전 남은 일

| 영역 | 현재 | 출시 전 작업 |
| --- | --- | --- |
| 기록 접근 | 인증 principal 기반 소유권, 다른 계정 거부 시험 | 모든 신규 API에도 같은 검사 및 실제 제공자 시험 |
| 로그인 | JWT 서명/issuer/audience/만료, 키 교체/장애 검증 | 카카오·구글 앱 등록, 로그인·갱신·로그아웃·탈퇴, 계정 연결 |
| 기기 저장 | 계정별 저장 분리, 실패/충돌 원문 보존 | 토큰은 플랫폼 보안 저장소 사용, 로그/백업 노출 검토. 일반 AsyncStorage를 암호화 저장소로 간주하지 않음 |
| DB 접근 | 로컬 주소에만 포트 노출, 환경변수 접속 정보 | 사설 접속/방화벽, 최소 권한 실행 계정, 마이그레이션 계정 분리 |
| 전송/비밀 | 원격 토큰 HTTPS 요구, JWKS 주소 검증 | 운영 TLS/인증서 검증, 비밀 관리·회전, 개발 인증 차단 |
| 백업 | 전용 시험 자료 백업·복원 검증 도구 | 운영 정기 백업·보관기간·복원 시점 목표와 실제 복구 연습 |
| 데이터 보존 | 명시적 삭제/충돌 선택 계약 | 회원 탈퇴, 계정 연결·분리, 개인정보/기록 보존 정책 확정 |
| 요청/로그 | 입력 범위·버전·요청 확인 번호, 토큰 미노출 | 요청량 제한, 악용 탐지, 로그 접근 권한·보존·민감값 검토 |

이 표는 운영 보안 인증이나 침투시험 완료를 뜻하지 않는다. 운영 배포 전에 실제 환경에서 검증하고 결과를 별도 기록한다.

검토 기준: [OWASP MASVS](https://mas.owasp.org/MASVS/), [OWASP Database Security](https://cheatsheetseries.owasp.org/cheatsheets/Database_Security_Cheat_Sheet.html). 세부 구현이 없는 항목은 계획으로 남기고 완료로 보고하지 않는다.
