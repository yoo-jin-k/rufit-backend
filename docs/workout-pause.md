# 운동시간 정지·진행

운동시간은 `(종료/취소 시각 또는 pausedAt 또는 현재 시각) - startedAt - pausedDurationMs`로 계산한다. 앱 종료·백그라운드·화면 잠금은 운동 상태를 바꾸지 않는다. 요청이 없어도 정지하지 않은 시간은 계속 흐른다.

| API | 요청 | 동작 |
| --- | --- | --- |
| POST /api/v1/workouts/{id}/pause | version | 서버 시각을 pausedAt으로 저장 |
| POST /api/v1/workouts/{id}/resume | version | 정지 구간을 pausedDurationMs에 더하고 pausedAt 해제 |

두 API는 인증된 소유자만 사용할 수 있다. 최신 버전에서 같은 상태로 반복 요청하면 상태와 버전을 바꾸지 않는다. 이전 버전은 409, 다른 소유자는 404, 종료/취소 후에는 409다. 응답 유실 시 GET으로 상태·버전을 확인하며 무조건 자동 재시도하지 않는다.

정지 중 메모/세트 수정은 가능하다. 세트 휴식은 별도 절대 종료시각이므로 운동 정지·진행으로 다시 시작하거나 연장되지 않는다. 정지 중 운동을 종료/취소하면 마지막 정지 구간까지 누적하고 정지 상태를 해제한다. 결과·주간·월간 운동시간 모두 정지 구간을 제외한다.

V22는 workouts에 nullable paused_at과 0 기본값의 paused_duration_ms를 추가한다. 과거 기록의 시간은 그대로다. DB CHECK가 종료 상태와 정지 상태의 동시 저장, 음수 누적시간, 종료/정지 구간보다 큰 누적시간을 막는다.

오프라인 가져오기는 선택 필드 pausedAt/pausedDurationMs를 받는다. 시작~현재 범위와 누적시간을 검증하며 종료된 운동은 pausedAt을 가질 수 없다. 과거 요청 또는 명시적인 null/0은 기존 v1 지문을 유지하여 배포 전 가져오기 재시도도 같은 요청으로 인식한다. 실제 정지 정보가 있으면 v2 지문에 포함한다.

프론트의 기기 저장 화면은 정지·진행 버튼과 시간 표시를 연결한다. 계정 연결 화면의 전용 요청 조율은 후속 작업이며 일반 세트 초안 저장으로 서버 타이머를 바꿀 수 없다. 운영 배포·실제 소셜 로그인 검증은 이 변경에 포함되지 않는다.
