# 서버 장시간 실행 검증

짧은 API 시험 외에 같은 JVM을 계속 사용하면서 DB 연결과 기록 흐름을 반복 확인합니다. `scripts/soak-backend.py`는 기존 개발·테스트 DB에 연결하지 않고 자신만의 PostgreSQL 컨테이너를 새로 만듭니다. DB·역할 이름은 `rufit_test`, 포트는 동적으로 할당한 루프백 주소, 비밀번호는 실행마다 생성합니다. 원래 환경변수의 DB 주소는 이 시험에 사용하지 않습니다.

Java 21, Docker와 이미 빌드·검증한 `target`의 실행 JAR가 필요합니다. 다음 명령은 6시간 동안 60초 간격으로 시험합니다.

```sh
python3 scripts/soak-backend.py --duration-seconds 21600 --interval-seconds 60
```

각 회차는 생성 키 재시도, 세트·완료·휴식·메모 일괄 저장, 같은 작업 재시도, 유휴 구간 뒤 활성 기록 일치, 운동 종료·요약·이력, 확인 삭제·중복 삭제, 삭제한 키 재사용 거절을 확인합니다. 맨몸 무게 0을 포함하며 원래 저장한 휴식 종료시각이 지나도 임의로 버전이나 기록을 바꾸지 않는지 봅니다. 개발 인증 시험이므로 긴 유휴 후에는 CSRF 세션 정보를 다시 받습니다.

서버 실행 파일은 임시 폴더에 복사한 고정 JAR이며 SHA-256을 결과에 기록합니다. 개발 중 새 빌드를 만들어도 시험 JVM이 읽는 파일은 바뀌지 않습니다. 요청 수·가장 긴 요청 시간·JVM 최대 관측 RSS·완료 회차·진행 상태를 `target/runtime-soak-result.json`에 원자적으로 갱신합니다. 결과에는 토큰·비밀번호·운동 본문을 넣지 않습니다. 숫자는 해당 환경의 관측값이며 성능 보장이나 부하 한계 측정이 아닙니다.

정상 종료와 SIGINT/SIGTERM 중단 시 시험 JVM을 종료하고 자기 실행 ID 라벨과 생성 CID 파일을 확인한 컨테이너·익명 볼륨만 정리합니다. 중단은 `interrupted`, 오류는 `failed`이며 정리 성공 여부도 별도로 기록합니다. 강제 종료(SIGKILL)나 컴퓨터 전원 종료는 정리 절차를 실행할 수 없으므로 남은 시험 JVM·컨테이너가 있는지 확인해야 합니다.

CI는 40초의 짧은 회차로 도구와 정리 절차만 검증합니다. 이 결과를 6시간 검증 완료로 해석하지 않습니다. 장시간 시험의 완료 여부는 해당 실행 결과의 `status`, 요청한 시간, 경과시간과 완료 회차를 함께 확인합니다. 외부 OIDC 키 갱신·실제 모바일 백그라운드 동작·다중 서버 운영은 이 시험 범위에 포함하지 않습니다.
