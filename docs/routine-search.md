# 루틴 검색과 페이지 조회

`GET /api/v1/routines/search?query=하체&page=0&size=20`은 본인 루틴의 이름을 부분 검색합니다. 앞뒤 공백과 영문 대소문자를 무시하며 `%`, `_`, `!`는 와일드카드가 아닌 글자 그대로 찾습니다. 빈 검색어는 본인의 전체 루틴을 조회합니다.

응답은 `items`, `page`, `size`, `totalElements`, `hasNext`입니다. 검색어는 최대 80자, 페이지는 0~10000, 크기는 1~50이며 기본은 첫 페이지 20개입니다. 이름과 ID로 정렬하여 같은 이름이 여러 개여도 데이터가 변하지 않는 동안 페이지가 안정적으로 나뉩니다. 페이지 사이에 루틴 이름 변경이나 삭제가 일어나면 목록을 다시 조회합니다.

기존 `GET /api/v1/routines?page=0`의 20개 배열 응답도 유지합니다. 새 앱 목록에서는 검색 API로 다음 페이지 여부를 판단할 수 있습니다. 각 조회는 반복 읽기 트랜잭션에서 목록·전체 개수·세트 구성을 읽습니다. 계정 조건과 기존 owner 인덱스를 사용하며 대규모 전문 검색 인덱스는 아직 추가하지 않았습니다.

검증은 실제 PostgreSQL에서 23개 동명 루틴의 페이지 중복 없음, 타 계정 제외, 전체 개수, 삭제 반영, 특수 문자 검색, 범위 오류와 기존 배열 응답 호환을 확인합니다.
