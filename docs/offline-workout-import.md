# 오프라인 운동 가져오기

`POST /api/v1/workouts/import`는 로그인한 사용자가 선택한 하나의 로컬 운동을 서버 기록으로 가져온다. 헤더 `Idempotency-Key`는 필수 UUID이며 생성되는 서버 운동 ID다. 요청의 `confirmed: true`는 해당 계정으로 가져오겠다는 명시적 선택에만 사용한다. 로그인 직후 익명 기록을 자동 이전하는 기능은 아니다.

```json
{
  "startedAt": "2026-09-12T09:00:00.000Z",
  "finishedAt": "2026-09-12T10:00:00.000Z",
  "sets": [
    {"set": {"exerciseName": "스쿼트", "weight": 1, "reps": 2}, "completed": true}
  ],
  "note": "오프라인에서 기록한 운동",
  "restSetIndex": null,
  "restEndsAt": null,
  "confirmed": true
}
```

| 입력/상황 | 처리 |
| --- | --- |
| startedAt | 필수. 1970-01-01부터 서버 현재 시각 사이. 입력 시각을 UTC 마이크로초로 보관 |
| finishedAt 없음/null | 진행 중 운동으로 가져오기. 서버에 다른 진행 중 운동이 있으면 409 |
| finishedAt 있음 | 시작부터 현재 시각 사이. 완료 세트가 하나 이상이고 모든 세트가 완료 상태여야 함. 미완료 행을 자동 삭제하지 않음 |
| 완료 운동과 서버 진행 운동 | 과거 기록 가져오기는 기존 진행 운동과 함께 저장 가능 |
| sets | 최대 300개, 기존 종목/무게/횟수 검증. 진행 중 초안만 빈 목록 허용 |
| exerciseId | 선택 사항. 지정하면 접근 가능한 활성 종목의 서버 이름 사용. 보관/타인/없는 종목을 임의 대체하지 않음 |
| restSetIndex/restEndsAt | 둘 다 있거나 둘 다 null. 완료 세트에만 연결. 최대 현재+3600초, 이미 지난 휴식은 재시작하지 않음. 완료 운동에는 휴식 불가 |
| note | 필수 문자열, 최대 2000자. 빈 메모는 빈 문자열 |
| 소유권 | 인증 principal에서 결정. 클라이언트 owner 이름/계정 지정 없음 |

성공·재시도는 모두 HTTP 200이며 `{workout, importedVersion: 0, replayed}`를 반환한다. 최초 가져오기는 버전 0에서 시작한다. 재시도는 현재 서버 기록을 반환하므로 나중에 수정·종료됐다면 `workout.version`은 `importedVersion`보다 높을 수 있다. 호출자는 이전 로컬 원문을 응답으로 자동 덮어쓰지 않아야 한다.

같은 UUID와 같은 최초 요청은 한 번만 가져온다. 원문 요청을 안정적인 v1 형식으로 해시해 `workouts.import_fingerprint`에 기록한다. 이름·세트 순서·무게·횟수·완료 상태·시각·메모·휴식이 바뀐 요청을 같은 UUID로 보내면 409다. 숫자의 불필요한 소수점 0은 동일 값으로 취급한다. 종목 이름 정규화/휴식 만료 처리는 최초 요청 해시를 바꾸지 않는다.

서버에서 후속 편집이 일어나도 재시도가 이전 내용을 덮어쓰지 않는다. 같은 식별자를 일반 운동 시작/루틴 시작과 바꿔 쓰지 못한다. 가져온 기록을 명시적으로 삭제하면 기존 retired_workout_keys에 식별자가 남아 같은 사용자의 재시도는 410, 다른 사용자의 충돌은 409이며 기록을 되살리지 않는다.

운동·세트·완료 상태·해시를 한 트랜잭션에 저장한다. 동시 요청에서 일시적으로 409가 발생할 수 있으며 같은 원문과 UUID로 재시도하면 기존 결과를 확인한다. 서로 다른 진행 중 운동을 동시에 가져오더라도 계정별 진행 운동은 하나만 저장된다.

## 클라이언트 연결 순서

1. 실제 로그인 계정과 가져올 로컬 운동을 사용자에게 보여주고 선택받는다.
2. 원문·로컬 행 ID·수정 번호·UUID와 준비한 요청 전체를 먼저 영구 저장한다. 불완전한 입력은 보존하고 전송을 보류한다.
3. 같은 준비 요청을 전송/재시도한다. 응답이 유실되면 새 UUID를 만들지 않는다.
4. 서버 결과와 저장 확인을 영구 저장한 뒤 로컬 항목을 연결한다. 전송 중 추가 편집과 원문은 별도로 유지한다.
5. 이미 종료된 가져오기 결과는 편집 중 폼으로 연결하지 않고 보관한다. 기존 연결 컨트롤러의 `link`는 진행 중 운동 전용이므로 완료 기록용 연결/영수증 복구가 추가로 필요하다.

현재 완료 범위는 백엔드 API·영속성·실제 PostgreSQL 시험이다. 원래 로컬 문자열/세트 ID를 보관하는 가져오기 대기 저장소, 서명 로그인 토큰으로 이 새 API를 호출하는 두 저장소 연결 시험, 실제 계정 선택 화면은 후속 작업이다. 카카오·구글 로그인 등록/화면, 운영 DB 배포, 이미지 교체와는 별도다.

정지 중인 운동은 선택 필드 `pausedAt`, 누적 정지시간 `pausedDurationMs`를 함께 가져올 수 있다. 상세 검증과 이전 요청 호환성은 [정지·진행 규칙](workout-pause.md)을 따른다.
