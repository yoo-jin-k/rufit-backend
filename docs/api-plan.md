# 구현 현황과 다음 단계

현재 동작하는 API 계약은 [운동·루틴 API](workout-api.md), [인증](authentication.md), [오류 응답](error-contract.md)에 정리한다. 런타임에서 생성한 OpenAPI 명세를 함께 검증한다.

| 영역 | 구현·검증한 범위 |
|---|---|
| 운동 기록 | 시작, 입력, 개별 세트 추가/인접 복제/수정/삭제, 완료 조건, 확인 취소, 명시적 정지/재개 |
| 루틴 | 저장/조회/수정/삭제, 이름 검색·페이지 정보, 독립 스냅샷 시작, 복사, 완료 운동에서 생성, 원본 삭제 후 재시도 |
| 종목 | 기본 카탈로그, 본인 사용자 종목, 검색·수정·보관·복원, ID와 과거 이름 보존 |
| 이전 기록 | 전체·날짜별·종목 ID/이름별 이력, 완료 기록 정정/삭제, 메모 |
| 세트/휴식 | 완료·취소, 절대 휴식 종료시각, 건너뛰기/±10초 조절, 종목별 추천·개인 지정·계정 기본값 |
| 저장/복구 | 활성 운동 복구, 버전 충돌 감지, 생성 키 재시도, 세트·완료·휴식·메모의 원자적 초안 저장, 원래 시각과 정지 상태를 보존하는 오프라인 가져오기 |
| 집계 | 주간·월간 달력, 종료 요약, 종목 누적 통계·최고 무게 세트, 수정·삭제 반영 |
| 비공개 프로필 | 본인 닉네임·소개·경험·목표, 버전 저장, 생성 재시도 |
| 인증 | Basic+CSRF, OIDC 서명·issuer·audience·시간 검증, 검증된 계정 식별자, HTTPS 키 주소·redirect 제한 |
| 서버 검증 | PostgreSQL 통합 시험, 동시 저장·조회 일관성, 중간 실패 롤백, JVM·컨테이너 재시작, DB 중단·재연결, 별도 DB 백업 복원 |
| 운영 준비 | 기본 업무 API 차단, 정확한 CORS origin, 요청 확인 번호, 상태만 공개하는 생존·준비 경로, 실행 이미지·OpenAPI 산출 |

프론트 저장소에는 검증된 계정 세션의 타입 API와 계정별 영속 초안 큐가 있다. 실제 서명 JWT와 PostgreSQL로 서버 통신·응답 유실 재시도·삭제된 초안 보존을 검증했다. 현재 운동 화면은 로컬 저장을 사용하며 이 서버 통신과 아직 연결하지 않았다.

| 남은 범위 | 상태 |
| --- | --- |
| 실제 회원 로그인 | 카카오·구글로 확정. 클라이언트 등록·모바일 로그인·토큰 갱신 연결 필요 |
| 화면의 서버 연결 | 인증 세션·초안 큐와 화면 연결, 사용자에게 충돌 선택을 받는 흐름 필요 |
| 계정 생명주기 | 회원 탈퇴, 계정 연결·이전, 삭제 방지 메타데이터 보존 정책 필요 |
| 사진·공개·소셜 | 프로필 사진, 선택적 공개, 헬스장·초대·채팅·신고·차단 미구현 |
| 출시 | 실기기 검증, 실제 HTTPS/로그인 제공자 통합, 운영 배포·백업 일정 필요 |

프론트 디자인은 추후 Figma 작업에 맞춰 변경한다. 검증용 데이터·로컬 로그인으로 실제 회원 계정이 만들어지지는 않는다. 자세한 실행 순서는 [연결·검증 안내](integration-guide.md)를 참고한다.

백엔드 전담 작업은 developer 기준 기능 브랜치에서 API 계약을 먼저 확정한 뒤 구현하고 developer PR로 제출한다. 새 작업은 PM 기준 codex/<기능>-<작업>으로 분리하고 기존 진행 feature/*는 보존한다. main/developer에 직접 수정·병합하지 않는다. 이전 develop 대상 PR을 포함해 현재 누적 PR은 의존 순서대로 검토해야 한다. 배포·병합 완료와 코드 구현 완료는 구분한다. 최신 상태는 [개발 현황](development-status.md)에 기록한다.
